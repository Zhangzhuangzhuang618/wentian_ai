# DEC-WT074-001 豆包整批连续采集编排

> 状态：已接受，开发态实机验证待完成  
> 日期：2026-08-25  
> 适用范围：问天独立版消费端工作台、豆包浏览器扩展、自动化预检与采集接口

## 背景

现有自动化仍以单任务为单位：用户每领取一题都要复制一次接入码、切换到豆包、完成采集后再回到问天领取下一题。该流程不能满足一次启动后连续处理同一运行全部待采集任务的需求。

## 决策

- 问天按运行签发一个两小时有效的整批接入码；接入码绑定系统实例、项目、运行、用户和本机问天来源；
- 用户在当前豆包页主动粘贴整批接入码并点击“连续采集整批”后，扩展留在当前页循环执行“领取下一题—预检—新建对话—发送—等待—采集—提交”；
- 整批接入码可以在有效期内重复领取，但不能直接上传回答。服务端每次只返回一个任务，并为该任务重新签发十分钟有效、一次性消费的采集凭证；
- 服务端优先恢复该用户已经处于`capturing`的任务，再按现有任务顺序领取第一条`waiting_user`任务；没有剩余任务时明确返回`complete`；
- 每一道题仍独立执行项目自动化开关、任务状态、地区、部署授权、页面签名和一次性凭证校验；运行中关闭自动化或授权失效会阻止领取或预检；
- 运行条件要求新对话时，扩展必须在可见页面找到并点击“新对话”控件；无法确认新对话已经建立时暂停，不能在旧会话中继续；
- 整批模式以用户一次批次启动作为本地导出确认，不逐题展示扩展预览；采集结果统一进入`needs_review`，必须回到问天逐项确认或驳回后才进入正式统计；
- 单题自动采集和手动选择流程保持不变，继续显示本地预览并要求单题确认；
- 用户可随时停止。失败时扩展保留当前内存中的批次码并允许重试；关闭页面、重新加载扩展或批次码到期后，需回到问天重新生成批次码；
- 第一版不新增数据库表、Redis、队列或跨浏览器持久状态。整批令牌使用现有部署密钥派生的独立HMAC用途签名。

## 安全与证据边界

- 整批模式不会绕过豆包生产授权门禁，也不会读取Cookie、Web Storage、隐藏网络响应或账号凭证；
- 扩展只操作用户当前激活的`https://www.doubao.com/chat/`可见页面；
- 自动提交只表示回答和截图已进入问天待复核区，不表示内容已经确认，也不计入排名；
- 同一任务的采集凭证保持一次性，批次码泄露窗口限制为两小时且只能访问绑定运行中的待采集任务；
- 当前实现不提供无人值守后台调度、跨标签页控制、验证码绕过、账号轮换或失败后无限自动重试。

`DEC-WT083-002`后，千问可见来源卡片允许一项受限例外：由当前千问页打开临时来源标签，读取URL后立即关闭。该例外不允许跨AI页面或跨账号编排。

## 取舍

无状态批次令牌避免为小规模测试引入任务队列和新的持久化模型。代价是浏览器或扩展重启后不能恢复面板内进度，需要从问天重新生成批次码；已成功提交的任务不会重复执行，服务端会从剩余任务继续。

## 验收

- 一个整批接入码可连续处理同一运行的多条任务；
- 每条任务仍获得独立短期采集凭证并执行完整预检；
- 停止、页面结构变化、问天不可用、发送失败和提交失败均暂停并允许重试；
- 新对话条件无法满足时失败关闭；
- 所有自动提交结果进入`needs_review`；
- 扩展权限没有增加；
- `pnpm verify`通过，真实豆包页面完成至少两题连续烟测后关闭任务。
