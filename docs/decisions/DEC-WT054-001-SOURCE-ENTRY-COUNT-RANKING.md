# DEC-WT054-001 同题信源条目累计排名

> 状态：已接受  
> 日期：2026-08-23  
> 适用范围：同一问题的提名侧或引用侧多次回答排名  
> 批准依据：项目所有者于2026-08-23确认按每次回答中的信源条目数累计

## 背景

现有重合计算只接收已经排序的域名集合。此前没有获批的跨回答排序口径，且现有部分指标样本会按域名去重，不能表达同一回答中同域名出现多条信源的情况。

## 决策

- 排名只能在同一个`querySnapshotItemId`、同一角色内计算；提名与引用分别排名，不混算；
- 每个已确认的正式信源条目计数一次，同一域名在同一回答或不同回答中重复出现时均逐条累计；
- 域名总次数按降序排列；总次数相同时按规范化域名字典序升序排列，保证结果可复算；
- 只接收已经通过上游证据确认的正式条目；待复核、已拒绝和仅存在于正文但未形成正式信源条目的内容不得进入排名；
- 结果返回总条目数、每个域名的累计条目数和确定性名次；
- 本指标是“信源条目累计次数”，不是“包含该域名的回答占比”，也不表示真实爬取频率、训练偏好或内部检索过程。

## 示例

第一次回答中A、B、C分别出现5、3、2条，第二次回答中A、C、D分别出现2、2、6条，则累计为A=7、D=6、C=4、B=3，排名依次为A、D、C、B。

## 影响

- 同一域名的多个信源条目不会被预先去重；
- 现有按域名去重的回答级指标样本不能直接作为本排名的输入；
- 后续运行级服务必须从正式提名/引用信源事件或等价的已确认明细构建排名；
- 排名可作为`NominationCitationOverlap@K`的上游输入，但仍需先通过配对运行可比性门禁。

## 排除方案

- 每个回答每个域名最多计一次：与已批准的条目累计口径不符；
- 用域名覆盖回答数或出现率排序：这是另一项指标，未获本决策批准；
- 把页面正文中的普通域名文本计入：无法证明其是正式信源条目。
