# DEC-WT039-001 消费端自述复核确认事务

> 状态：已接受  
> 日期：2026-08-22  
> 适用范围：已确认消费端自述响应的人工解析复核  
> 批准依据：`CHG-VIS-002`的“确认事务创建正式nominated事件”规则

## 背景

WT-038已提供复核Repository，但单独保存confirmed review再逐条创建来源事件会产生部分成功。确认请求也不能接受客户端补交run、问题项、样本槽位、scope或来源哈希，否则可能把提名事件挂到错误响应。

## 决策

- 复用已确认消费端响应作为服务端身份事实，不新增重复响应模型；
- 确认命令只接受scope选择、review ID、期望版本、人工修订项和发生时间；
- 应用服务通过review反查不可变响应，再通过响应反查运行；
- 只允许`experiment_kind=source_nomination`且已有服务端派生`nomination_context`的运行确认提名；
- 事件的scope、run、response、问题快照项和样本槽位全部从响应派生；
- 事件固定为`human_confirmed`，域名规范化和`source_key_hash`由服务端投影器完成；
- 终态review与完整事件集合通过单一事务端口全有或全无；
- 事务适配器在写入前复核review、响应、事件完整性、逐项绑定、唯一键和版本冲突；
- 当前仅有内存原子实现，不声称等同于PostgreSQL生产事务。

## 影响

- 客户端无法把人工提名挂到另一运行或伪造来源键；
- 空提名列表仍可确认，表示“已人工确认但没有显式域名”，并生成零事件；
- 事件ID或唯一键冲突时review仍保持`needs_review`；
- API幂等键、生产审计和PostgreSQL锁仍需后续实现。

## 排除方案

- 新建仅用于事务的重复响应身份表：与现有不可变响应事实重叠；
- 客户端提交run/query/sample：扩大越权和错绑面；
- 先保存review再批量写事件：不是原子确认；
- 允许自然回答运行创建nominated事件：混淆实验口径；
- 用cited事件代替nominated事件：违反证据角色隔离。
