# DEC-WT044-001 自述复核解析溯源字段

> 状态：已接受  
> 日期：2026-08-22  
> 适用范围：`ai_nomination_parse_reviews`当前领域记录与内部DTO  
> 变更类型：批准基线后的最小审计增强

## 背景

批准基线只列出`proposed_items_json`，没有保存提取器版本、有效/拒绝显式项数量和截断状态。解析器升级后，仅凭当前候选列表无法解释历史候选如何产生；人工确认又允许增删候选，不能用确认后的列表长度反推初始解析结果。

## 决策

- review增加不可变`extraction_version`；
- 增加不可变`initial_proposed_item_count`；
- 增加不可变`valid_explicit_occurrence_count`、`rejected_explicit_occurrence_count`和`extraction_truncated`；
- 未截断时有效显式出现数必须等于初始候选数；截断时初始候选必须为10且有效出现数大于10；
- `needs_review`和`rejected`的当前列表必须保持初始候选数；
- `confirmed`允许人工修订后列表数量变化，但初始候选数和解析统计不变；
- Repository保存终态时把全部解析溯源字段视为不可变身份的一部分；
- 严格读模型公开这些质量字段，不公开回答正文或来源哈希。

## 影响

- 历史review可解释使用了哪个提取版本、是否截断及有多少无效显式项；
- 人工修订不会覆盖原始解析质量事实；
- 生产表落地时需要把这些字段加入新迁移，不能静默复用批准基线DDL；
- 当前仍不保存完整原始候选副本，只保存最小计数溯源。

## 排除方案

- 只在应用日志记录版本：日志保留期和业务记录生命周期不一致；
- 把版本写入reason：污染模型提名理由语义；
- 用确认后列表长度覆盖初始计数：丢失人工修订差异；
- 保存全部解析中间token和匹配区间：当前需求不需要，超出最小范围。
