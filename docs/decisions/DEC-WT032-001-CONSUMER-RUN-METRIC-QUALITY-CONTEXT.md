# DEC-WT032-001 单运行消费端指标质量上下文

> 状态：已接受  
> 日期：2026-08-22  
> 适用范围：内部单运行消费端指标批次、查询结果与只读DTO草案  
> 批准依据：`CHG-VIS-002`数据质量标记要求和项目所有者持续推进授权

## 背景

WT-030与WT-031已经能从终态自然回答运行按需计算指标，但原批次只保留scope、run、问题集哈希、归一化版本和样本。运行的实验类型、采集方式、问题集来源、GEO契约版本和历史Surface身份会在计算边界丢失，调用方无法仅凭报告确认指标来自哪种实验条件。

这些字段已由批准基线定义，不需要重新设计指标公式；需要决定的是它们在内部链路中的可信来源和校验位置。

## 决策

单运行指标批次必须保存以下质量上下文：

- `querySetSourceType`；
- `geoConnectorContractVersion`；
- `experimentKind`；
- `collectionMethod`；
- `nominationContext`；
- `surfaceProfileVersionId`；
- `consumerSurfaceCode`。

上下文只能由WT-030读取的冻结运行、问题集快照和历史Surface版本派生：

- GEO契约版本取自运行绑定快照；`geo_sync`必须有版本，其他来源必须为空；
- 当前消费端可见引用指标只接受`natural_answer`，因此提名上下文必须为空；
- 批次中每个样本的采集方式和Surface必须与运行上下文一致；
- WT-017物化读取和WT-031按需读取共用同一个上下文校验与计算入口；
- 返回DTO继续是未发布的`@0-draft`，不注册HTTP路由。

DTO中的`observation_verification_status`描述进入指标分母的证据状态，不描述整个运行的所有任务状态：有可用指标时为`confirmed`，无确认样本时为空。`evidence_grades`由单运行采集方式派生；浏览器辅助对应`web_confirmed_capture`，人工录入对应`web_confirmed_manual`。Provider专属质量字段和对照字段在当前消费端单运行响应中显式为空，不能伪造。

## 影响

- 运行级批次无法再丢失质量上下文后单独物化；
- 响应可辨认运行、问题集来源、采集方式和Surface版本；
- 当前计算器继续拒绝`source_nomination`，提名指标需要独立公式和任务；
- 不从当前GEO连接器实例、当前Surface配置或客户端请求反查历史上下文；
- 不改变现有可见引用率、首位引用率、稳定度或样本基数公式。

## 排除方案

- 从指标分组反推运行上下文：分组没有问题集来源、GEO契约版本和运行身份；
- 在DTO适配时由调用方补字段：无法证明字段与指标样本属于同一运行；
- 立即发布公共指标路由：跨运行筛选、生产数据源和访问边界尚未完成；
- 把失败任务统一写成`confirmed`：会混淆运行结果与进入指标分母的证据状态。
