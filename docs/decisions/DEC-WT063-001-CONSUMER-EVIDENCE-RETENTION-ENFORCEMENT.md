# DEC-WT063-001 消费端证据保留期执行

## 状态

已接受，日期：2026-08-23。

## 决策

- 保留期必须由PostgreSQL与对象存储协调清理，不能只依赖对象存储生命周期；
- 待复核包24小时到期后删除对象和Artifact，将任务置为`expired`并原子重算运行；
- 无上传结果的`capturing`任务停留24小时后置为`expired`；
- 已确认截图30天后删除对象及截图哈希，保留删除审计墓碑；
- 已确认回答和可见引用180天后删除正文、原始标签、说明文字、回答哈希及Artifact；
- 正式事件仅保留规范链接、域名、位置、方法版本和必要审计身份，继续支持累计排名和配对对照；
- 每次清理写`retention_cleanup_runs`，明显位于未来的截止时间失败关闭；
- 第一版由部署主机每天调度一次Compose维护任务，不引入Redis或常驻Worker。

## 后果

保留策略从文档声明变成可执行删除。原始证据过期后不可重新复核，但已经人工确认的正式信源事实和统计仍可复算。
