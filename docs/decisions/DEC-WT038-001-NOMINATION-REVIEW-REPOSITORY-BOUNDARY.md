# DEC-WT038-001 自述解析复核Repository边界

> 状态：已接受  
> 日期：2026-08-22  
> 适用范围：自述解析复核记录的内部持久化端口与内存实现  
> 批准依据：`CHG-VIS-002`的一对一复核、scope隔离和终态约束

## 背景

WT-037已固定复核记录的领域状态机，但尚不能按scope读取待办、保证同一响应只有一条复核记录，也不能拒绝并发旧写入。确认事务若直接绕过这些约束，会使同一响应出现多条复核或终态被陈旧版本覆盖。

## 决策

- 应用层定义`SourceNominationParseReviewRepository`端口；
- `id`全局唯一，`scope_id + response_id`一对一；相同响应ID在不同scope中相互隔离；
- 所有读取都要求服务端已经确定的scope，跨scope按不存在处理；
- 待办读取按状态过滤，并以创建时间和ID确定性排序；
- 创建和保存前重跑领域完整性校验；
- 保存使用`expectedVersion`乐观锁，只接受`version = expectedVersion + 1`；
- ID、scope、response和创建时间不可变；只允许`needs_review`保存为`confirmed`或`rejected`；
- 当前实现只提供内存适配器，不声称具备生产持久化、审计历史或数据库事务能力。

## 影响

- 后续应用服务可在不依赖具体数据库的情况下读取和推进复核；
- 同一响应不能出现多条待复核记录；
- 陈旧审核提交不会覆盖已经终结的结果；
- “复核确认 + nominated事件”仍需独立原子事务端口，不能把两个Repository调用当成生产原子性。

## 排除方案

- 只按review ID查找而不隔离scope：会泄露资源是否存在；
- 把重复响应创建当成幂等成功：无法证明候选内容相同；
- Repository允许终态任意覆盖：破坏不可逆状态机；
- 先保存review再逐条写事件：会留下部分成功状态。
