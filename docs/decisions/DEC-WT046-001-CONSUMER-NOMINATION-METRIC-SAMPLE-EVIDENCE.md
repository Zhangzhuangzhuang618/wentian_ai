# DEC-WT046-001 消费端自述指标样本证据边界

> 状态：已接受  
> 日期：2026-08-23  
> 适用范围：消费端`source_nomination`响应到WT-034指标样本的内部投影

## 背景

WT-034只定义指标样本，WT-039/040建立了人工确认或拒绝后的复核终态和正式`nominated`事件。若指标直接读取人工复核列表，会绕过正式事件的来源键、归一化版本和不可变归属校验；若忽略待复核或拒绝响应，又会静默缩小成功样本分母。

## 决策

- 每个已确认消费端自述响应必须与同scope、同response的复核记录绑定；
- `confirmed`复核只从完整正式`nominated`事件集合生成`human_confirmed`指标样本；
- 事件集合必须与响应的run、query、sample及复核时间、域名、顺序、信息类型和理由逐项一致；
- 域名和来源键必须再次通过当前固定归一化版本的完整性校验；
- `needs_review`和`rejected`仍各生成一个成功响应样本，但提名数组必须为空，且不得存在正式事件；
- 样本ID固定使用不可变response ID，避免另造无法回溯的聚合身份；
- 投影层不读取回答文本、不重新解析、不创建事件。

## 影响

- 指标中的人工确认事实以正式事件为准，复核列表只负责证明事件集合应是什么；
- 所有成功响应都能在指标输入中显式出现，解析状态不会被静默丢弃；
- `registrableDomain`必须已经是可注册域，子域名不能伪装成该字段；
- 当前只形成内部投影，不发布HTTP或生产持久化。

## 排除方案

- 直接把confirmed review列表当指标事实：绕过正式事件审计链；
- 把待复核样本从成功分母删除：会提高表面提名率；
- 从回答正文再次解析：会使历史结果随解析器版本漂移；
- 对名称或子域名做隐式猜测：超出显式证据边界。
