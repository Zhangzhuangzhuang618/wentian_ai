# DEC-WT033-001 消费端人工录入证据边界

> 状态：已接受  
> 日期：2026-08-22  
> 适用范围：消费端现场人工录入到观察包提交DTO的转换  
> 批准依据：`CHG-VIS-002`的`web_observed + manual_import`兜底路径

## 背景

批准基线把现场人工录入定义为浏览器辅助不可用时的MVP兜底，但现有实现只有通用提交DTO和浏览器草稿适配器。若人工录入界面直接构造通用DTO，就可以自行声明采集方式、Adapter版本或DOM对象引用，弱化服务端证据边界。

## 决策

建立独立、严格的人工录入输入Schema和纯函数适配器：

- 调用方只提交任务版本、回答原文、页面可见引用、可见会话元数据和截图媒体资产ID；
- `collection_method`由适配器固定为`manual_import`；
- `adapter_version`由适配器固定为`wentian-manual-import@1`；
- 人工录入不接受DOM对象键；
- 输入继续严格拒绝Cookie、Token和未声明字段；
- 人工录入提交后仍为`needs_review`，后续必须通过既有确认事务才能产生`web_confirmed_manual`证据；
- 该适配器不注册HTTP路由，也不接收真实数据。

## 影响

- 人工录入无法伪装成浏览器辅助采集或自定义Adapter；
- 截图和页面条件仍是必填证据，不因人工录入而放宽；
- 通用提交DTO保持不变，正式处理器仍须按任务、Surface和运行上下文复核；
- 后续UI可以依赖这一输入边界，但当前任务不实现UI或上传。

## 排除方案

- 复用浏览器草稿：人工录入没有页面选择器和本地扩展导出语义；
- 允许客户端传采集方式：会使证据等级可被调用方间接控制；
- 人工录入直接确认为有效证据：绕过`needs_review → confirmed`人工确认生命周期；
- 允许人工附带DOM：无法证明DOM来自目标页面和采集时点。
