# DEC-WT059-001 问天独立版第一版基础设施

> 状态：已接受  
> 日期：2026-08-23  
> 适用范围：问天独立部署第一版  
> 批准依据：项目所有者于2026-08-23明确批准技术组合和依赖边界

## 决策

- 数据库固定为PostgreSQL 16；
- 证据对象使用S3兼容对象存储，Docker Compose开发/单机部署默认提供MinIO；
- 身份采用问天本地账号，不依赖GEO账号；
- 首个Owner通过一次性初始化流程创建，初始化成功后永久关闭，不提供默认账号、默认密码或公开注册；
- 交付Docker Compose部署清单；
- 数据库迁移编号从`0001`开始，严格顺序执行并校验文件SHA-256；
- 第一版不依赖Redis，不启动独立队列服务；当前人工领取、提交、复核和按需计算使用API进程与PostgreSQL完成；
- 第一版不包含GEO连接器，GEO不可用或未配置不影响问天启动、登录和核心readiness；
- readiness只检查PostgreSQL和S3兼容对象存储，不再虚构Redis/队列依赖。

## 与批准基线的差异

`CHG-VIS-002`独立部署文档曾把Redis/Worker列为最小生产组件。本决策缩小第一版范围：暂不引入Redis和独立Worker。只有出现已批准的异步任务、并发和重试需求后，才通过新ADR增加队列；不得为了与旧拓扑图一致而先部署空队列。

## Owner初始化

- 部署方预先生成高熵初始化令牌，只把SHA-256摘要提供给初始化进程；
- 初始化命令接收一次性明文令牌、本地Owner邮箱、显示名和密码；
- 令牌采用常量时间比较，密码使用带独立随机盐的`scrypt`摘要保存；
- PostgreSQL事务锁定唯一实例行，创建Owner和实例成员关系后写入初始化时间；
- 任意后续初始化尝试返回`OWNER_ALREADY_INITIALIZED`；
- 初始化秘密不得写入镜像、Compose默认值、数据库明文、日志或仓库。

## Docker Compose边界

- 长期组件仅为`postgres`、`object-store`和`api`，另有一次性`object-store-init`与`migrations`初始化任务；
- PostgreSQL和对象存储不发布到公网；示例端口只绑定本机；
- Compose变量使用显式必填秘密，不提供可直接用于生产的默认密码；
- `api`必须等待迁移成功后启动。

## 影响

- readiness契约移除`queue`字段；
- `0001_standalone_foundation.sql`成为首个且不可重编号的迁移；
- GEO连接器和Redis不进入第一版验收；
- 后续业务表只能从`0002`继续。
