# DEC-WT061-001 豆包用户在场采集与独立持久化

## 状态

已接受，日期：2026-08-23。

## 背景

此前豆包扩展只能本地预览和导出JSON，领域运行、任务、证据、正式回答及信源事件主要使用内存仓库。问天重启后无法保留实验，也没有把截图写入已批准的S3兼容存储。

## 决策

- 激活`doubao_web`的用户在场采集Surface，只允许`browser_assisted | manual_import`；
- “激活用户在场采集”不激活生产自动提问。自动提问仍必须通过项目开关和外部授权/官方接口证据双门禁；
- 扩展继续要求用户主动点击、选择可见回答、本地预览和平台最终确认；不读取豆包账号、Cookie、Token、localStorage或隐藏网络响应；
- 运行、任务、待复核证据、正式回答和`cited`信源事件持久化到PostgreSQL；正式事件和回答追加写入；
- 截图正文只写入私有S3兼容对象存储，数据库保存对象键、SHA-256、大小、保留级别和到期时间；
- 待复核截图保留24小时，确认后转为30天；拒绝时删除对象和暂存记录；
- 采集令牌为HMAC签名、短期、绑定实例/scope/任务/用户/Origin且nonce只能消费一次；
- 数据库迁移序号使用`0002`，不修改`0001`。

## 后果

问天可以形成重启后仍可复算的消费端观察事实，并能把用户在场豆包采集接入真实任务。页面自动操作能力仍未获得生产授权，因此不得由该Surface激活推导出自动提问可用。
