# DEC-WT040-001 自述复核拒绝事务

> 状态：已接受  
> 日期：2026-08-22  
> 适用范围：消费端自述解析复核拒绝  
> 批准依据：`CHG-VIS-002`的“拒绝不创建来源事件”规则

## 背景

拒绝动作虽然不写来源事件，但若仅保存`rejected`状态而不检查已有事件，系统可能出现“解析已拒绝、正式提名事件仍存在”的证据矛盾。读取后检查再单独保存也存在竞态，因此需要与review版本更新处于同一事务边界。

## 决策

- 拒绝命令只接受scope选择、review ID、期望版本、拒绝原因和发生时间；
- 服务端通过review反查不可变响应与`source_nomination`运行，不接受客户端归属字段；
- 复核状态机派生审核人、审核时间、拒绝原因和下一版本；
- 事务提交前复核review与响应绑定，并确认该scope和response没有任何正式`nominated`事件；
- 只有“无事件”条件和全部版本/完整性校验同时通过时才保存`rejected`终态；
- 拒绝事务从不创建、更新或删除正式来源事件；
- 当前内存实现只验证事务语义，生产数据库仍需行锁和同事务查询。

## 影响

- 拒绝结果与正式提名事实不会同时存在；
- 若系统已存在异常事件，拒绝会失败关闭并保留`needs_review`供治理；
- 不允许通过拒绝动作删除不可变来源事件；
- API幂等、审计事件和生产事务继续留待后续。

## 排除方案

- 拒绝时删除已有事件：违反正式来源事实不可删除；
- 先查询事件再调用普通Repository保存：存在竞态；
- 不检查响应和运行：可能拒绝错误实验中的记录；
- 让客户端声明“没有事件”：不是服务端事实。
