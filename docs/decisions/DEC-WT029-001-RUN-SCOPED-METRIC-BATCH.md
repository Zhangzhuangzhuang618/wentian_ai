# DEC-WT029-001 内部消费端指标批次按运行隔离

> 状态：已接受  
> 日期：2026-08-22  
> 适用范围：内部消费端指标样本批次与读取服务  
> 批准依据：`CHG-VIS-002`筛选隔离要求和项目所有者持续推进授权

## 背景

WT-017最初用`scope_id + query_set_snapshot_hash`标识一个指标批次。同一scope可以针对相同问题集重复创建不同Surface、实验类型、采集方式、会话条件或时间窗口的运行；继续使用该键会拒绝合法并存，或在生产实现中造成覆盖。

批准基线要求最终聚合缓存键包含scope、方法版本和筛选哈希，但当前公共筛选契约尚未完整实现。此时定义跨运行合并规则会提前决定窗口、运行选择和配置兼容性。

## 决策

当前内部消费端指标批次改用`scope_id + run_id`作为唯一读取身份，并继续在批次内保存问题集哈希和归一化版本：

- 一个批次只代表一个运行；
- 相同问题集的多个运行可以并存；
- scope权限仍在读取前校验；
- Repository返回的scope和run身份必须与查询一致；
- 问题集哈希只作为报告事实，不再充当批次唯一键；
- 不自动聚合或覆盖其他运行。

## 影响

- 内部查询由`scope + snapshot hash`改为`scope + run ID`；
- 批次增加不可缺少的`runId`；
- 该决策不定义公共HTTP查询参数，也不等同于最终筛选哈希；
- 后续跨运行聚合必须先形成完整筛选契约，并以新的任务或ADR替换本临时内部身份；
- 已批准指标公式、样本资格和证据语义不变。

## 排除方案

- 继续以问题集哈希唯一：会冲突或覆盖不同运行；
- 立即实现跨运行筛选哈希：筛选字段、窗口和运行选择尚未完整落地；
- 把run ID加入问题集哈希：会破坏问题集内容等价语义。
