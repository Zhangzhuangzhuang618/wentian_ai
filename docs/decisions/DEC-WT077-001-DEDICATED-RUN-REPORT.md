# DEC-WT077-001 独立运行结果详情页

> 状态：已接受  
> 日期：2026-08-25  
> 适用范围：问天独立版消费端观察工作台、自然回答排名、信源对照展示

## 背景

当前“排名与信源对照”会把每个问题的完整域名表连续铺在工作台中。问题和域名数量增加后，用户很难先看到整次运行的结论，也无法快速比较任务完成度、问题差异和头部信源。项目所有者要求从工作台点击详情后进入单独标签页，并增加任务汇总、单问题统计和图表。

## 决策

- 已终结的自然回答运行在运行列表中提供“查看结果”入口；“排名与信源对照”保留运行选择，并提供“打开引用详情”和“打开对照详情”；
- 详情使用同源URL在新的浏览器标签页打开，路由只携带`scope_id`、运行ID和报告模式，不携带Cookie、密码、CSRF令牌、回答正文或对象存储位置；
- 详情页继续使用问天本地HttpOnly会话。登录态失效时显示登录页，重新登录后按原URL继续加载报告；
- 工作台不再渲染全部问题的长排名表，只说明独立详情页包含的内容；
- 自然回答详情展示：任务确认数/任务总数、问题数、正式信源条目总数、独立域名数、出现正式信源的问题比例、全运行Top 10域名、单问题信源密度、单问题汇总表和可展开域名排名；
- 信源对照详情展示：两次运行任务确认情况、可计算问题数、平均Top 10重合、实际引用与AI自述的域名图、单问题对照表和双侧可展开排名；
- 图表使用原生HTML进度条和文本标签，不引入第三方图表依赖；表格和可展开明细保留精确数值，图表只承担视觉比较；
- 页面展示模型由现有严格任务、排名和对照响应在浏览器内可复算生成，不新增数据库、迁移、缓存、后台作业或权威指标接口；
- 所有统计继续遵循现有证据语义：只累计已确认回答中的正式可见信源；AI自述与实际引用分开；重合不代表内部抓取路径。

## 展示口径

- “任务确认”=`confirmed`任务数/当前运行全部任务数；
- “正式信源条目”=各问题正式排名中的条目数之和，同一域名每出现一条计一条；
- “独立域名”=当前运行所有问题正式排名的域名并集大小；
- “问题覆盖”=正式信源条目数大于0的问题数/问题总数；
- “每回答平均”=单问题正式信源条目数/该问题已确认任务数；没有已确认任务时显示不可用；
- “平均Top 10重合”只平均`availability=available`的问题，不把不可用问题按0计入。

以上均为详情页展示汇总，不创建新的领域指标事实源；单问题接口返回值和既有方法版本仍是最终依据。

## 取舍

第一版按问题复用现有排名接口，因此一次报告会产生“任务列表1次＋每问题排名1次”的只读请求。批准问题集上限为100题，当前实验规模为个位数至几十题；本轮不为此增加聚合API或缓存。后续只有在真实负载证明需要时才新增服务端运行汇总契约。

## 验收

- 工作台不再展示连续长问题表，可从运行列表和排名区打开独立详情；
- 新标签页的项目和运行必须仍通过现有scope权限校验；
- 自然回答详情显示四项汇总、两个图表、单问题表和可展开排名；
- 信源对照详情显示可比性、双侧任务汇总、双侧图表和单问题对照；
- 图表值可以从表格及接口返回的精确数值复算；
- 无信源、待复核、不可比较、登录失效和资源不存在时有明确空态或错误态；
- 不新增数据库迁移和第三方前端依赖；
- `pnpm verify`通过，并在当前已完成运行上完成浏览器新标签页验证。
