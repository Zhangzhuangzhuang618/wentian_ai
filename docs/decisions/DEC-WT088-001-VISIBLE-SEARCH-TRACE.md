# DEC-WT088-001 页面可见检索轨迹、分析与导出

> 状态：已接受
> 日期：2026-08-31
> 适用范围：消费端浏览器采集、证据确认、检索词洞察与 Excel 导出

## 背景

部分消费端回答页会明确展示“搜索 N 个关键词，参考 M 篇资料”、具体检索词及参考资料列表。现有问天只保存回答正文、可见引用和截图，没有结构化保存这些页面可见检索词，无法用于项目级复盘或导出为 GEO 关键词素材。

## 决策

- 新增“页面可见检索轨迹”证据，固定与原问题、运行、采样、平台、地区、行业、观察时间和确认记录绑定；
- 轨迹只记录页面明确显示的摘要、检索词顺序、声明关键词数量和声明参考资料数量，不推断隐藏请求、平台内部抓取词、抓取频率或权重；
- `complete`要求声明关键词数量与可见检索词条目数一致；无法完整读取时记为`partial`，页面未提供同类信息时记为`not_present`；历史记录缺少该字段时展示为`not_collected`，不得反推补齐；
- 同一采样内同一规范化检索词只累计一次，跨采样累计；首版只执行Unicode NFKC、首尾空白、连续空白和大小写归一化，不合并同义词；
- 项目级“检索词洞察”独立于四步实验工作流；运行详情增加“检索词”视图，任务预览增加“可见检索词”和“参考资料”分区；
- Excel固定包含`关键词汇总`、`关键词明细`、`参考资料`和`口径说明`四张工作表，保留完整URL；默认只导出已确认且轨迹完整的数据；
- Excel文本执行公式注入防护，导出沿用当前项目权限和筛选条件；
- 豆包作为首个支持完整检索轨迹的Surface；千问和DeepSeek只有在页面出现等价可见证据时才允许升级支持，当前不得构造检索词。

## UI取舍

- 不增加第五个实验步骤，避免把检索词误解为独立采集阶段；
- 不引入新的前端框架，继续使用现有原生模块和设计令牌，先拆分分析页与证据预览；
- 不在工作台堆叠完整报表，项目级分析和运行详情使用独立视图。

## 验收

- 新豆包采集可预览并提交页面可见检索词、声明数量及参考资料数量；
- 不完整轨迹不阻断回答与引用采集，但有清晰状态且默认不进入导出；
- 已确认数据可按项目、运行、平台、地区、行业和问题筛选；
- Excel四张工作表可由常用办公软件打开，URL完整且危险公式文本不会执行；
- 历史记录保持可读取，显示“当时未采集”，不伪造空值或补齐值；
- `pnpm verify`、数据库升级和真实浏览器烟测通过。
