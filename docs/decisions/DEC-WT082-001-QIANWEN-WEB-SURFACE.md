# DEC-WT082-001 千问 Web 消费端观察 Surface

> 状态：已接受  
> 日期：2026-08-26  
> 适用范围：消费端观察运行、浏览器扩展、自动化预检、证据复核与信源统计

## 背景

问天现有消费端观察只注册`doubao_web`，创建运行、任务领取、扩展页面白名单和采集草稿均写死豆包。千问当前正式 Web 入口为`https://www.qianwen.com/`。仅增加前端选项会导致千问证据被错误标记为豆包，因此必须同步扩展 Surface 契约、持久化配置、页面驱动和证据绑定校验。

## 决策

- 新增受控 Surface `qianwen_web`，产品标签为“千问网页版”，允许`browser_assisted`与`manual_import`；
- 千问页面仅允许`https://www.qianwen.com`根路径、`/chat`和`/conversation`会话路径；其他路径失败关闭；
- 任务领取、自动化预检、扩展当前页面和上传草稿的 Surface 必须一致；不允许跨平台证据串写；
- 扩展只读取用户当前可见页面、所选回答区域内的文本、HTTP(S)链接和屏幕截图；不读取Cookie、Web Storage、账号凭证、隐藏网络响应或页面私有状态；
- 千问首版只把回答区域内真实可见的HTTP(S)链接作为正式引用，不对媒体名、域名文字或隐藏来源面板作推断；
- 单题和整批自动提问复用现有可见页面驱动，但使用独立页面签名`qianwen-web-signature@1-visible-page`和独立部署门禁；
- 自动化开关仍默认关闭。生产环境必须具备书面许可、证据编号和90天内复核时间；当前本机可使用`synthetic`进行小规模开发测试；
- 所有自动提交结果仍进入`needs_review`，经问天人工确认后才进入正式统计；
- 既有豆包运行及证据不迁移、不改写。

## 取舍

首版不实现千问私有来源面板解析，也不使用网络拦截补齐链接。页面结构无法识别、发送状态不明确、回答未稳定或新对话入口不可用时暂停当前任务，避免生成不可核验证据。

## 验收

- 可分别创建豆包和千问运行，运行记录明确显示观察对象；
- 千问任务领取和预检返回`qianwen_web`、千问官网 Origin 与独立页面签名；
- 扩展可在千问官网打开，不能在其他千问路径或第三方页面启动；
- 千问草稿通过严格契约，产品标签和Origin不能与Surface错配；
- 单题、整批任务保持平台一致，新对话条件失败时暂停而不提交；
- 上传端再次校验运行Surface并写入`qianwen-web@1-attended`；
- 自动化默认关闭，生产授权缺失时失败关闭；
- 全量`pnpm verify`、数据库迁移、服务健康检查通过。

## 依据
