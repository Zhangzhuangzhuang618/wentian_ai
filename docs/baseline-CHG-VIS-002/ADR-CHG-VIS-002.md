# ADR：CHG-VIS-002 “问天”AI信源探测系统与GEO连接器

## 状态

已接受。批准日期：2026-08-21。可据此建立问天独立项目开发基线；不得直接修改GEO Content OS v2.1冻结文档。

## 背景

ADR-0022建立了AI可见度问题集、模型记忆测试、品牌提及和竞品分析。现有首期只使用DeepSeek模型API、每题单样本、`model_only`模式，并明确不宣称为联网搜索结果。

新需求是针对固定问题测量AI回答中的搜索候选、最终引用及来源倾向，增加“AI自述应参考哪些信源”的声明偏好实验，在没有API时采集消费端网页实际可见回答与引用，并结合企业自有站点日志测量AI爬虫真实访问频率。现有GEO实现虽预留部分枚举和样本字段，但没有搜索Provider、信源提名、消费端观察、关系化来源事件、多样本统计和爬虫日志域。该能力需要能够完全独立部署，同时保留从GEO进入和同步项目上下文的能力。

## 决策

### 产品边界

- 产品正式命名为“问天”AI信源探测系统。
- 问天只有一种运行形态：完整独立部署；自带身份、项目、权限、数据库、API、Worker、UI、用量和审计。
- GEO Content OS通过 `wentian-geo-connector@1` 薄连接器接入，只提供导航、一次性SSO、项目绑定、问题集同步和可选事件回传。
- 项目绑定采用GEO管理员发起、问天管理员选择本地项目并批准的双端流程；未批准状态不能SSO或同步。
- GEO不运行问天核心代码或Worker，不执行问天迁移，不直连问天数据库、Redis或对象存储，不共享Cookie或Provider凭证。
- 问天MVP为单组织、多项目系统，不建设公共多租户SaaS。
- 一个问天MVP实例只允许绑定一个GEO租户，可绑定该租户下多个项目；多GEO租户接入另行评审。
- 问天独立版MVP先行发布；GEO连接器是后续集成里程碑，不阻塞独立版上线。
- `model_only`、`search_api`、`web_observed`、`imported` 四种运行模式保持独立口径。
- 固定模式组合：`model_only/search_api → provider + provider_api`，`web_observed → consumer_surface + browser_assisted/manual_import`，`imported → external_dataset + manual_import`。
- `web_observed` 只用于有明确消费端surface和会话条件的现场观察；`imported` 只用于无法归属为现场消费端观察的历史或外部数据集。消费端人工录入仍写为 `web_observed + manual_import`。
- 站点爬虫访问、搜索候选、最终引用作为三个独立观察层。
- 信源自述提名作为独立声明层，不进入实际引用率或爬虫频率。
- 消费端网页可见回答和引用作为 `web_observed` 层，不代表隐藏搜索候选。
- 自动探测只使用正式、获授权、允许保存和分析必要引用元数据的API。
- 消费端MVP允许用户主动触发的浏览器辅助采集和人工导入，禁止自动登录、无人值守批量操作、验证码处理以及读取凭证、Cookie、Token或隐藏网络响应。
- API结果必须显示真实Provider与model ID，不标记为消费端产品结果。
- API—消费端对照使用 `exact | approximate | query_only` 等级；无法用公开证据证明模型等价，或运行时页面模型未知/与版本化映射不符时默认 `query_only`，只允许同题并列观察。

### MVP范围

- 复用现有版本化问题集的产品语义；问天本地创建不可变快照，或由GEO连接器同步后创建相同格式快照；
- 运行开始后只读取问天快照，不回调GEO问题集；
- GEO接入使用版本化连接器契约、显式项目绑定和签名服务端请求；
- 每题支持1–5个独立样本，默认3；
- 增加 `experiment_kind = natural_answer | source_nomination`，两类实验独立运行；
- 增加 `nomination_context = unaided | search_assisted | surface_unknown`；非联网自述、搜索辅助自述和消费端模式未知自述不得混合统计；
- 自述实验使用版本化提示词和 `nominated` 事件，明确禁止声称真实抓取频率；
- 增加 `web_observed` 运行模式、消费端surface能力快照、观察任务、可见证据包和人工确认闭环；
- 增加SearchProbeAdapter统一契约；
- 首个Provider候选为OpenAI Responses Web Search；第二Provider候选为Perplexity Sonar；两者上线均以条款和账号能力评审为前提；
- 暂不接入Gemini Grounding with Google Search，除非取得适用于本产品分析用途的书面许可并通过法务评审；
- 保存原始回答、候选/引用必要元数据、请求ID、用量和版本化URL归一化结果；
- 不主动抓取第三方引用网页正文；
- 日志首期采用CSV导入，支持已验证自有域名；
- AI爬虫默认必须通过User-Agent与官方IP范围双重核验。

### 指标

- 引用率、引用份额、首位引用率、平均引用位置；
- 候选曝光率、候选转引用率；
- 提名率、首位提名率、提名稳定度和提名—引用重合度；
- Web端可见引用率、Web端来源稳定度和API—消费端重合度；
- 问题覆盖率与来源稳定度；
- 已验证爬虫请求数、页面覆盖率、抓取成功率、发现/重访延迟；
- 每项指标返回分子、分母、方法版本和数据可用性；
- MVP只做描述性统计，不自动宣称显著性或因果关系。

### 数据与运行

- 在问天数据库建立run/response等业务表，保存运行快照与样本进度；不扩展GEO历史业务表；
- 问天业务数据按项目scope隔离；GEO租户、工作区和项目外部引用只保存在连接器绑定表中；
- GEO外部身份映射与项目访问映射分开；角色和访问版本按project binding隔离，拒绝或断开的binding保留历史引用且不得覆盖复用；
- 新增Provider能力版本、来源事件、自有域名、消费端surface版本、观察任务、可见证据包、日志导入、最小请求事实和爬虫身份快照表；
- 来源事件使用必填 `source_key_hash` 支持只有域名、没有URL的提名；`url_hash` 在无URL时允许为空；
- 消费端确认状态与证据等级分开：确认状态使用 `not_required | needs_review | confirmed | rejected`，证据等级使用 `api_structured | web_confirmed_capture | web_confirmed_manual | imported_declared`；
- 原始响应和来源事件append-only；聚合可重算；
- 运行创建、问天用量记录与问天Outbox同事务；问天本地预算是运行门禁的唯一事实；
- Worker按 `scope + run + query_snapshot_item + sample_index` 幂等；
- 外部未知态不伪造成功，不生成额外样本；
- API密钥只从环境变量或密钥服务读取。

### UI

问天Web包含概览、模型记忆、联网信源、消费端观察、爬虫日志五个页签。GEO连接器只提供连接状态、项目绑定、问题集同步和“进入问天”入口，不复制或iframe嵌入问天页面。所有报告固定披露API探测、自述声明、消费端可见结果和内部真实行为之间的差异；默认爬虫指标只包含双重核验的请求。

## 备选方案

### 方案A：全自动化消费端网页

拒绝进入MVP。存在账号条款、反自动化、验证码、页面易变、隐私和结果不可复现问题。采用用户主动触发、人工确认的浏览器辅助采集作为受控替代。

### 方案B：只统计回答正文里的URL

拒绝。无法区分候选与引用，且正文URL可能由模型生成或缺失，不能形成可靠证据。

### 方案C：问天与GEO各实现一套探测能力

拒绝。两套领域逻辑、迁移和UI会产生指标漂移与双倍维护成本。探测能力只能存在于问天，GEO只保留连接器。

### 方案D：问天同时以GEO内嵌模式运行

拒绝。两个启动入口、两套身份和基础设施装配会扩大实现与验收范围。问天保持唯一独立运行形态，GEO通过远程Integration API接入。

### 方案E：GEO与问天共享数据库或会话

拒绝。共享数据库、Cookie或会话密钥会破坏故障隔离和独立升级。采用显式API、一次性票据和签名Webhook。

### 方案F：只做服务器日志

拒绝作为完整方案。日志能测爬虫访问，不能测具体回答的搜索候选和最终引用。

## 后果

### 正面

- 建立可追溯的信源观察链路；
- 将模型记忆与联网引用分开；
- 可解释自有站点从访问到候选再到引用的不同缺口；
- 问天可独立安装、升级、备份和恢复；
- GEO故障不影响问天核心运行；
- GEO接入范围收敛为连接器契约，避免维护两套运行环境测试矩阵。

### 负面

- 外部API成本明显增加；
- Provider字段和条款可能变化；
- 多样本仍只能提供观察性结果；
- 日志身份快照与隐私处理增加运维责任；
- API结果不能完全代表消费端产品。
- 信源自述容易被误读为内部真实偏好，需要长期保持独立标签和方法说明；
- 消费端页面变化会导致采集适配器暂停，并产生持续维护成本。
- 需要维护问天Integration API与GEO侧连接器的版本兼容；
- SSO票据、项目绑定、同步和Webhook增加一条跨系统运维链路；
- GEO用户会离开GEO外壳进入问天Web，首期不是原生嵌入体验。

## 安全与合规

- Provider上线必须记录条款复核、允许字段、保留期和责任人；
- 日志只处理已验证自有或获授权域名；
- 原始IP仅用于核验，按策略脱敏；
- 不保存Cookie、Authorization或非必要日志字段；
- 不fetch第三方引用URL；
- 浏览器辅助采集不读取消费端凭证、Cookie、Token或隐藏网络响应；
- 消费端观察未经人工确认不进入默认指标；
- 消费端误采内容在上传前本地丢弃；已上传观察包被拒绝时删除暂存证据，只保留拒绝原因和审计记录；
- 问天项目导出、删除、备份和恢复覆盖新增数据与对象；GEO解绑不得静默触发数据删除。

## 迁移与兼容

- 问天使用独立迁移序列，不修改GEO历史迁移；
- 现有运行按单样本保留，原有品牌可见度分数不变；
- 现有GEO历史运行不自动搬入问天；需要迁移时使用显式导出/导入任务和独立ADR；
- 历史运行默认 `experiment_kind=natural_answer`；新增 `web_observed` 通过新迁移扩展约束；
- 历史 `imported` 记录不自动改判为 `web_observed`；
- 不从历史 `citations_json` 反推candidate事件；
- GEO现有DeepSeek `model_only` Worker与UI继续按原基线运行，但不与问天新运行共用事实表。

## 验收

- 一个搜索Provider完成问题集→多样本运行→来源下钻闭环；
- 信源自述完成提名→人工复核→提名/引用对照闭环；
- 消费端观察完成任务→用户采集→预览确认→可见引用报告闭环；
- 指标黄金数据完全一致；
- API/Provider结果标识准确；
- 部分成功、幂等、预算、取消和用量正确；
- 日志导入双重核验正确，UA-only不进入默认指标；
- 项目隔离、连接器契约、SSRF、CSV、隐私和可访问性测试通过；
- contracts、迁移、OpenAPI和文档无漂移。
- 全新环境完成问天安装、初始化、运行、升级、备份和恢复测试；
- GEO停止或连接器网络中断时，问天核心readiness和既有运行保持正常；
- SSO、绑定、同步、回调签名、重放防护和解绑数据保留测试通过；

## 实施前待确认事项

1. 首批Provider和模型ID；
2. Provider条款是否允许所需聚合、保留和导出；
3. 默认样本数与预算上限；
4. 原始回答和日志保留期；
5. 自有域名验证方式；
6. 正式任务号和迁移序号；
7. 第二Provider、通用外部数据集导入UI和创建Brief是否进入后续增强；消费端现场人工录入已属于MVP。
8. 首批消费端产品、允许采集范围和页面适配器维护人；
9. 消费端截图与DOM保留期；
10. 自述提示词、Top-K和异常声明复核规则。
11. 消费端surface与API模型的等价等级和证据来源；无法证明时必须保持unknown。
12. 问天首发部署编排、备份介质和初始化秘密交付方式。
13. GEO连接器首发是否只包含SSO与项目绑定，还是同时包含问题集同步和事件回传。
14. GEO角色到问天项目角色的最终映射与会话失效时限。
