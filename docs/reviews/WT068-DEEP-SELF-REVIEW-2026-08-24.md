# WT-068深度自审

> 日期：2026-08-24  
> 结论：开发与合成测试范围通过；真实豆包生产自动提问继续受授权和实机烟测门禁阻断

## 自审范围

- 自动化预检接口、一次性接入码和任务绑定；
- 项目开关、地区、授权类型、授权证据和90天复核门禁；
- 浏览器扩展权限、自动输入、发送、完成判断、采集和人工确认；
- Docker Compose默认配置、真实PostgreSQL 16与MinIO端到端演练；
- 契约、任务、部署手册和扩展说明一致性。

## 发现与修复

### 1. 浏览器不能成为授权事实源

一次性接入码是可解码的传输包，不能在其中加入可被页面伪造的自动化开关或授权字段。现改为扩展必须调用本机问天预检；服务端重新校验令牌、实例、项目、任务、用户、版本、项目设置和部署配置，只在全部通过后返回当前任务问题。

### 2. 授权编号不能永久放行

首次实现只要求授权类型和证据编号，未落实既有“最长90天复核”规则。现新增部署侧复核时间：缺失、格式非法、位于未来或距当前超过90天均失败关闭。网页驱动仍只接受`written_permission`，`official_interface`不能替代。

### 3. 重复回答可能被误判为旧回答

初版合成选择器按回答全文排除提交前内容；新回答与旧回答文字完全相同时会被错误忽略。现改为按提交前DOM节点身份建立基线，新插入节点即使文本相同也可以进入候选，同时排除会随会话增长的旧父容器。

### 4. 页面仍在生成时可能采集半成品

自动采集同时要求：当前豆包聊天页签名匹配、候选可见、文本长度有效、停止生成控件不可见、文本连续稳定5秒。最长等待3分钟；任一条件不满足时不上传并回退手动选择。自动结果仍需本地预览和问天最终确认。

### 5. 扩展权限可能随自动化扩大

扩展权限保持`activeTab + scripting`及本机HTTP地址，没有新增Cookie、存储、下载、网络监听、外部主机或跨标签页权限。页面脚本不直接发网络请求；预检和提交只由后台脚本发送到接入码中再次校验过的`127.0.0.1/localhost`来源。

### 6. 单元测试不能证明真实部署路由已接通

除纯策略和合成页面判定外，已在名称、端口和数据卷完全隔离的Docker Compose实例中运行真实端到端验证。结果确认默认项目开关会阻断自动化预检，同时排名、提名—引用对照、保留期清理和项目删除继续通过。演练后的容器、网络和PostgreSQL/对象存储测试卷均已删除且无残留。

## 验证结论

- 自动化默认关闭；生产授权默认`none`；
- 服务端预检不消费一次性令牌，最终上传成功后才消费；
- 生产书面授权、证据编号和90天内复核时间同时满足时，合成链路可进入`ready`；
- 自动结果不能绕过本地预览、最终确认或`needs_review`；
- 完整`pnpm verify`通过；
- 隔离Docker端到端验证返回`automation_preflight_default_blocked=true`和`scope_deleted_without_residue=true`。

## 仍未满足的上线门禁

1. 豆包提供的、明确覆盖可见网页自动化用途的书面许可及证据编号；
2. 项目Owner与合规责任人90天内的授权复核时间；
3. 已授权真实账号上的输入框、发送控件、停止生成状态、回答候选和失效回退烟测；
4. 上线环境HTTPS、备份恢复、密钥轮换和干净CI回归。

上述门禁不阻止代码开发和合成测试，但未满足前不得把真实页面自动提问标记为已上线。
