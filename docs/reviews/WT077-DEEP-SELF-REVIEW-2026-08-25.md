# WT-077 深度自审

> 日期：2026-08-25  
> 结论：实现、全量自动验证、服务重建和浏览器实机验收通过

## 自审范围

- 详情路由、会话恢复和项目隔离；
- 任务汇总、域名聚合、单问题统计和平均重合口径；
- 图表与精确表格的一致性；
- 工作台信息密度、空态、移动端和无障碍；
- 独立部署、静态资源与新增依赖影响。

## 发现与处理

| 编号      | 风险                                   | 处理                                                             | 结果   |
| --------- | -------------------------------------- | ---------------------------------------------------------------- | ------ |
| SR-077-01 | 详情页把客户端汇总误当成新的权威指标   | ADR明确所有汇总均由既有严格响应可复算，单问题接口仍是事实源      | 已处理 |
| SR-077-02 | URL泄露凭证、回答或证据位置            | URL只保存scope、运行ID和模式；身份继续使用同源HttpOnly会话       | 已处理 |
| SR-077-03 | 修改URL读取其他项目或运行              | 每个任务、排名和对照请求继续执行现有scope与资源绑定校验          | 已处理 |
| SR-077-04 | 登录失效后详情入口丢失                 | 登录页保留原详情URL，成功登录后继续选择原项目并恢复报告          | 已处理 |
| SR-077-05 | 图表舍入后与精确数据不一致             | 图表保留整数条目数并配套精确表格；百分比只作展示，原始分子不改写 | 已处理 |
| SR-077-06 | 不可用问题被按0计入平均重合            | 平均值只使用`availability=available`问题，并增加纯函数测试       | 已处理 |
| SR-077-07 | 图表无法被辅助技术理解                 | 使用带`aria-label`的原生`progress`，同时提供文本、数字和表格     | 已处理 |
| SR-077-08 | 大量结果继续挤占工作台                 | 工作台只保留详情说明，精确排名放入新标签页并按问题折叠           | 已处理 |
| SR-077-09 | 为展示需求引入大型图表依赖或新基础设施 | 使用原生DOM/CSS，不新增依赖、数据库、迁移、缓存或后台作业        | 已处理 |
| SR-077-10 | 移动端表格截断导致数据不可读           | 表格允许横向滚动；汇总和图表在窄屏改为单列                       | 已处理 |
