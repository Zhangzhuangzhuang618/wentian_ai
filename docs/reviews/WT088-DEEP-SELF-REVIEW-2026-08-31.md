# WT-088 深度自审

> 日期：2026-08-31
> 结论：通过
> 未关闭项：无

## 审核范围

- 豆包页面可见检索摘要、检索词和资料数量的采集；
- 草稿、提交、证据 Artifact、不可变确认记录和保留期；
- 项目级检索词洞察、运行下钻、筛选和 Excel 导出；
- 历史兼容、权限、公式注入、证据口径和响应式界面；
- 类型、自动测试、分层、OpenAPI、Docker 部署和浏览器验收。

## 证据边界

- 系统只记录回答页明确显示的检索轨迹，不读取网络请求、Cookie、Token 或平台内部日志；
- `complete`要求声明关键词数量与读取条目数一致；`partial`、`not_present`和历史`not_collected`分别展示；
- 只有已确认且`complete`的采样进入默认排名和 Excel 关键词统计；
- 历史记录不从回答正文或引用反推，当前 82 次历史采样正确显示为“当时未采集”；
- 该数据不能解释为平台内部真实检索词、抓取频率、隐藏候选或权重。

## 数据与安全

- 检索轨迹进入证据哈希，修改词序、数量或内容会破坏完整性校验；
- 旧 Artifact 和确认记录缺少新字段时仍可读取，不需要数据库迁移；
- 新字段跟随现有确认记录和原始证据的保留、清理及项目删除生命周期，不延长保存期限；
- API 继续执行本地会话和项目权限校验，未登录访问返回 401；
- Excel 固定四张工作表，保留完整 URL，文本经过公式注入防护；
- 页面最多展示 200 个词和最近 80 次采样，完整结果由 Excel 提供。

## 本次发现并修复的问题

1. API 分析模块最初直接导入领域包，违反项目依赖方向；已改为经应用层公开类型，并通过边界检查。
2. 新增 HTTP 测试最初按传统`filename=`断言，实际接口正确使用 RFC 5987 的`filename*=`；已修正测试并保留中文文件名。
3. 运行详情在 768px 视口下因 Grid 子项最小内容宽度产生 64px 横向溢出；已给报告主体直接子项设置`min-width: 0`，复测后`scrollWidth`与`clientWidth`均为 768px。
4. 首次真实整批烟测的 40 条 Artifact 都只保存了检索摘要和声明数量，关键词数组为空；根因是扩展在展开参考资料面板前读取检索词。已改为面板展开后轮询最多 1.5 秒，读取完整词组后再收起面板。
5. 豆包空白新对话页出现“问题已填入但未触发发送”；根因是页面处理粘贴后虽显示文本，但内容编辑器未收到统一的`input`和`change`事件。扩展`0.0.26`改为完成文本写入后始终补发两类事件，真实页面复测已恢复自动发送。
