# WT-088 产品、交互与 UI 审核

> 日期：2026-08-31
> 审核范围：问天独立版消费端观察工作台、运行详情和新增页面可见检索词数据

## 审核结论

现有界面适合完成“问题集—运行—采集—对照”的线性实验，但不适合承载跨运行、跨问题的检索词资产。把检索词继续堆入第四步会混淆实验流程和分析结果，因此不增加第五步，也不整体迁移前端框架；本次采用页面级信息架构调整。

## 发现的问题

| 问题                                   | 影响                                           | 处理                                                      |
| -------------------------------------- | ---------------------------------------------- | --------------------------------------------------------- |
| 四步工作流承担创建、操作和分析三类职责 | 结果越多，工作台越长，用户难以判断当前位置     | 在侧边栏新增独立“检索词洞察”，四步流程保持不变            |
| 任务预览只展示回答与链接               | 无法在确认前判断检索词是否读取完整             | 增加检索轨迹状态、摘要、词条和声明资料数                  |
| 运行详情只展示域名排名                 | 无法从同一运行查看检索词、问题和资料之间的关系 | 增加检索词指标、Top 图表和单采样下钻                      |
| 原生长下拉框不适合动态运行数据         | 内容增长后难找、截断、滚动过长、误选           | 运行筛选沿用可搜索选择器，显示主标题与元信息              |
| 域名汇总不足以供 GEO 使用              | 丢失原问题、检索词顺序和完整参考 URL           | 新增汇总、明细、参考资料和口径说明四表 Excel              |
| 历史数据没有检索词字段                 | 空值容易被误解为“页面没有检索词”               | 明确展示“当时未采集”，禁止从回答或引用反推                |
| “搜索词”容易被理解为平台内部真实行为   | 结论可能越过可观测证据边界                     | 全局统一命名为“页面可见检索词/检索轨迹”，持续展示口径提示 |

## 信息架构

- `消费端观察`：保留问题集、实验运行、采集复核、排名对照四步；
- `检索词洞察`：项目级跨运行分析，支持运行、平台、行业、地区和问题/检索词筛选；
- `任务预览`：确认前查看回答、检索轨迹和完整参考链接；
- `运行详情`：在域名统计之外增加当前运行的检索词统计和下钻；
- `Excel`：按当前筛选条件导出可用于 GEO 关键词整理的数据。

## 关键交互

- 默认排名只使用已确认且轨迹完整的采样；不完整数据仍可在证据下钻中查看；
- 同一采样内规范化后相同的词只累计一次，跨采样累计；
- 检索词表最多展示前 200 项、证据列表展示最近 80 次采样，完整数据通过 Excel 获取，避免页面失控；
- 所有参考资料在详情和 Excel 中保留完整 `https://...` URL；
- 平台、行业、地区、运行和文本筛选共同作用于页面与导出。

## 视觉取舍

- 延续现有深色导航、浅色工作区、紫色主操作和青绿色证据状态；
- 用指标卡、汇总表和可展开证据卡形成“概览—排序—下钻”三级信息密度；
- 不进行整套视觉品牌重做，不引入 React/Vue 或图表库；首版优先保证证据口径、可追溯性和可维护性。

## 后续验收重点

- 1280、1440 和窄屏下不发生操作区重叠；
- 搜索选择器、筛选、清除、Excel 导出和浏览器前进后退可用；
- 历史采样、完整轨迹、不完整轨迹和页面未显示四种状态可区分；
- 真实豆包页面的摘要、词序、数量和参考资料与问天预览一致。
