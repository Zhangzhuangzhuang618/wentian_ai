# WT-084 深度自审

> 日期：2026-08-26  
> 结论：数据语义、历史兼容、筛选、生成器、权限和部署验证通过

## 自审范围

- 项目和问题集的业务地区、行业归属；
- 运行目录继承规则与采集地区代码的隔离；
- 历史快照结构、内容哈希和幂等创建；
- 项目元数据更新的角色、scope、CSRF和并发门禁；
- 可搜索选择器、项目/问题集/运行筛选和空态；
- 行业问题批量生成的数量、意图、可编辑性和来源边界；
- 迁移、静态资源、测试和本机服务。

## 发现与处理

| 编号      | 风险                                               | 处理                                                          | 结果   |
| --------- | -------------------------------------------------- | ------------------------------------------------------------- | ------ |
| SR-084-01 | 把`CN_MAINLAND`当作业务地区会混淆“广州”等分析标签  | 业务地区保存在项目/问题集；会话地区代码继续独立保存在运行条件 | 已处理 |
| SR-084-02 | 根据项目名或问题文本自动推断历史标签会制造错误事实 | 0010只增加可空字段，历史记录显示“未设置”，由管理员明确补录    | 已处理 |
| SR-084-03 | 新字段加入哈希后导致旧快照完整性校验失败           | 仅当快照实际包含业务元数据时加入哈希，旧JSON继续按原结构重建  | 已处理 |
| SR-084-04 | 运行重复保存地区行业后可能与问题集漂移             | 运行目录按关联问题集投影，不新增运行字段                      | 已处理 |
| SR-084-05 | 项目标签覆盖并发更新                               | PATCH要求当前版本，成功后版本加一，旧版本返回冲突             | 已处理 |
| SR-084-06 | 长下拉框无法定位同名或历史运行                     | 动态选择器改为输入搜索，标签包含业务标签、平台、时间或短ID    | 已处理 |
| SR-084-07 | 筛选可能改变或删除当前数据                         | 筛选只作用于已加载视图；提供清除按钮和无结果空态              | 已处理 |
| SR-084-08 | 模板问题被误认为外部AI或真实用户数据               | 生成器完全本地、确定性、带版本；保存前进入可编辑文本区        | 已处理 |
| SR-084-09 | 用户改写问题后意图仍错误继承                       | 只按完整文本匹配模板意图；改写条目回退到表单默认意图          | 已处理 |
| SR-084-10 | 可搜索选择器在注册表声明前初始化导致页面脚本中断   | 浏览器烟测发现后调整初始化顺序，重载后6/6选择器正常初始化     | 已处理 |

## 保留边界

- 既有项目和问题集不会自动补齐地区、行业；需在项目“编辑标签”或新建问题集时明确填写；
- 当前筛选在一次加载的目录中执行，不是服务端全文检索或分页；当单项目达到数千条运行并出现真实性能问题时再立项；
- 模板只降低首轮录入成本，不代表平台真实高频问题，也不代替用户复核；
- 内容完全相同的快照仍按内容幂等复用，来源元数据不改变既有跨来源去重规则；
- 本轮浏览器烟测未代替用户登录，也没有为了测试创建、修改或删除业务数据。
