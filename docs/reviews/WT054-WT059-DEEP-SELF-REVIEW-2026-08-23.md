# WT-054～WT-059深度自审

> 日期：2026-08-23  
> 范围：多回答信源累计排名、配对实验可比性、提名—引用对照、豆包自动化治理、独立版第一版基础设施  
> 结论：所列任务在各自发布边界内完成；问天完整独立产品尚未完成

## 1. 已确认的产品语义

- 同一问题、同一来源角色内，每个正式信源条目计一次；同一回答中的同域名条目不去重；
- 多次回答按域名累计条目数降序排名，并列时按规范化域名确定性排序；
- 用户示例复算结果为`A=7、D=6、C=4、B=3`；
- 两次配对实验使用实际`startedAt`的绝对时间差，恰好24小时允许，超过1毫秒拒绝；
- 时间、scope、快照、Surface、采集设置、会话和搜索上下文必须满足配对门禁；
- 自动化开关默认关闭。打开开关只表达项目意图，不等于已取得第三方平台生产自动化授权；
- 第一版独立基础固定为PostgreSQL 16、S3兼容对象存储、本地账号、一次性Owner初始化、Docker Compose和从`0001`开始的迁移；不依赖Redis和GEO连接器。

## 2. 深度自审发现与修复

1. 既有指标样本会按域名去重，不能满足“每个信源条目都计数”的新规则。对照服务已改用正式、不可变信源事件重新累计。
2. 运行时语言环境可能影响`localeCompare`结果。并列规则已改为规范化域名的Unicode码点顺序，保证跨环境一致。
3. “24小时”若使用创建时间会偏离实际实验。门禁只使用两侧实际开始时间，并覆盖恰好24小时和超过1毫秒边界。
4. 仅检查运行ID不足以防止跨scope或跨问题串证据。服务补充了快照身份、scope、哈希、问题数量和问题项一致性，以及响应、复核、事件、样本序号的逐层绑定检查。
5. DTO可能被调用方附加“抓取频率”等不可核验结论。严格契约拒绝额外字段，并复算排名总数、顺序、名次、样本可用性和重合输入。
6. 自动化开关可能被误解为生产许可。策略采用双门禁：项目开关与第三方授权/官方接口证据必须同时满足；未知授权依据和空地区策略失败关闭。
7. 早期readiness仍含队列概念，与第一版“不依赖Redis”冲突。现已移除队列检查，并由严格契约阻止该字段回流。
8. 迁移只记录版本不足以防止历史文件被修改。运行器加入SHA-256漂移、连续编号、数据库超前和事务/锁检查。
9. 仅启动MinIO并不代表证据桶存在。Compose新增一次性建桶任务，API须等待迁移和建桶成功后启动。
10. 环境变量示例中的示例秘密可能被直接沿用。秘密值全部留空，并在部署手册中要求外部注入。
11. 本机既有服务占用常用端口。演练使用隔离项目名和`64321`～`64324`端口，不触碰其他项目；演练后删除专用容器、网络和合成数据卷。

## 3. 验证证据

- `pnpm verify`通过：类型检查、329项测试、架构边界、独立基础检查、OpenAPI一致性、格式和文档检查全部通过；
- Docker镜像成功构建；
- PostgreSQL 16从空卷应用`0001_standalone_foundation.sql`成功，第二次迁移为空操作；
- Owner首次初始化成功，第二次返回`OWNER_ALREADY_INITIALIZED`；
- 数据库核验为一个Owner，密码摘要为`scrypt`格式且无明文密码；
- MinIO健康，一次性任务成功创建`wentian-evidence`桶；
- API就绪响应同时报告`database=ready`、`objectStore=ready`；
- 演练结束后，专用容器、网络和合成数据卷已删除。

## 4. 未完成且不得误报为完成的事项

- 对照能力目前是内部应用服务和严格DTO，尚无公开HTTP接口及可操作UI；
- 豆包真实页面的自动提交、回答采集和批量运行尚未实现；当前生产自动化仍被`draft + authorization=none`门禁阻断；
- 保留期目前是策略事实源，实际定时清理和对象生命周期作业尚未实现；
- 本地账号目前只有数据库结构、密码能力和Owner初始化，尚无登录/退出、会话轮换、CSRF及管理UI；
- 既有运行、证据和指标仓库大部分仍为内存/合成实现，尚未迁移到PostgreSQL；
- S3兼容存储目前完成启动、建桶和readiness，尚无证据上传、下载和删除Repository；
- GEO连接器未实现，符合第一版不依赖GEO的批准范围；
- Redis和独立Worker未实现，符合第一版批准范围。

## 5. 客观结论

WT-054～WT-057已经形成可复算、失败关闭的内部信源对照核心；WT-058完成的是自动化控制和治理门禁，不是真实豆包生产自动化；WT-059完成的是独立部署基础，不是完整独立产品。下一批开发应优先补齐持久化仓库、证据对象存储、登录会话、清理作业，以及对照查询的HTTP/UI闭环。
